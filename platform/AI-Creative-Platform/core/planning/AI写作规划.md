# AI 写作规划（Layer 3 · 规划者 / Planning）

> **定位**：五层/七层架构的 **Layer 3 —— 规划者**。
> 位于 **L2 规范之后、L4 Workflow 之前**。先输出**章节规划卡**，禁止「边写边想」。
> 解决用户指出的缺口：目前流程直接开始写，缺规划层，AI 容易想到哪写哪。

---

## 1. 规划卡（Chapter Plan Card）字段

本文件说明 Story Beat 的写作方法；机器可执行的完整字段以
`core/contracts/outline.schema.yaml#chapter_plan` 为唯一契约。除下表字段外，
规划卡还必须包含开始状态、四类目标、场景进入/退出状态、因果链、读者体验、
信息释放、预期状态变化、OOC/连续性约束、下一章承诺和可调整边界。

| 字段 | 内容 | 对应下游 |
|------|------|----------|
| 章节目标 | 本章要达成什么（情节推进 / 人物成长 / 伏笔推进） | L2 生成规范·目标；L4 写正文 |
| 剧情节拍 | 宏观结构：起 → 承 → 转 → 合（章节骨架） | L4 正文结构 |
| Story Beat（微节拍） | 每个场景按自身目标组织 3–7 个节拍；五拍结构只是可选模式，不是全章固定模板 | L4 正文节奏控制 |
| 冲突设计 | 核心冲突 ＋ 对抗双方 ＋ 升级点 | `checks/conflict.md`（CF01 真实冲突） |
| 情绪曲线 | 预设计：平 → 紧张 → 高潮 → 释放 → 悬念 | `checks/reader/emotion.md`（情绪曲线检测） |
| 章节预算 | 字数分配：开头 / 铺垫 / 冲突 / 高潮 / 结尾 | L2 规范·层5 预算；`checks/chapter.md` |

---

### 1.1 Story Beat（微节拍 · 自适应控制）

> Story Beat 用于把场景变成可执行动作链，但不得把每章都切成同一五拍。
> AI依据场景类型、人物选择和信息任务选择 3–7 拍；五拍只适合具有完整冲突升级的章节。

| 拍 | 名称 | 作用 | 必含 | 字数占比（参考） |
|----|------|------|------|------------------|
| 1 | **Hook（钩子）** | 开篇即抓：承上 / 置疑 / 危机 | 末句前已抛悬念或冲突 | 10–15% |
| 2 | **Inciting（激励事件）** | 触发本章核心冲突 | 明确「要解决的麻烦」 | 15–20% |
| 3 | **Escalation（升级）** | 阻力加码、信息释放 | 对抗升级 / 新变量入局 | 30–35% |
| 4 | **Climax（高潮）** | 冲突顶点、爽点 / 转折 | 最大张力 / 关键决断 | 25–30% |
| 5 | **Resolution（收束）** | 落定 + 钩子 | 留追更悬念（B2） | 10–15% |

- 每拍登记：**动作主体 / 目标 / 阻力 / 信息变化 / 情绪变化 / 状态结果**。
- 调查章可以采用“线索→假设→验证→修正”，对话章可以采用“试探→隐藏→施压→权力变化”，
  情感章可以采用“触发→抵抗→选择→余波”，不强制设置人工高潮。
- L4 Workflow 按场景计划推进；没有状态变化的节拍必须删除。
- 字数占比由本章 `narrative_strategy` 决定，不使用跨章统一比例。

## 2. 规划原则

- **先于生成**：规划卡齐全前不得进入 L4 Workflow 写正文。
- **承接规范**：L2 生成规范已定「目标 / 冲突 / 高潮 / 钩子」，本层将其**展开为可执行规划卡**（节拍、情绪曲线、预算具体化）。
- **可被审查核对**：规划卡是 L5 Review 的「预期」基准——审查可比对「实际成稿」是否偏离规划卡（目标完成？冲突达成？情绪曲线符合？预算均衡？）。

---

## 3. Exit → 进入 L4

- `platform outline chapter-check` 通过；
- 规划卡满足 `outline.schema.yaml#chapter_plan`；
- 与 NKB / 宪法 / 规范无冲突；
- 本章具备真实剧情进展、读者收益和状态变化。

以上全部满足后才允许进入 L4 Workflow。

---

## 4. 与架构的关系

```
L2 规范（行为）──▶ L3 规划者（本章规划卡＋Story Beat）──▶ Context Engine（建运行时上下文）──▶ L4 Workflow（按卡写）
```

> 规划者产出「计划」，Context Engine 产出「背景」，Workflow 产出「正文」——三者顺序不可颠倒。
