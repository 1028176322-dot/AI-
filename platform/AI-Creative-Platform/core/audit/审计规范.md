# 权限审计规范（Audit & Accountability）

> 层级：Platform Layer — 审计系统
> 对应 Phase 1「必须」项：审计
> 配套契约：`core/contracts/audit.schema.yaml`
> 工具：`tools/audit_log.py`（append-only jsonl）

## 1. 为什么需要审计

平台从「聊天驱动」变为「任务调度」后，必须记录**谁、何时、用什么模型、执行了什么操作、改了什么文件、结果如何**——类似企业系统审计。

用途：
- 追责：某章被谁改崩了，一查便知；
- 追溯：配合 task + version，定位「问题引入于哪次操作」；
- 合规：满足 `requires_human` 节点的人工确认留痕；
- 恢复：失败时可从审计链重建现场。

## 2. 存储

```
<project>/
└── audit/
    └── audit.log.jsonl     # 每行一条 JSON 记录，append-only
```

- 仅追加，不可修改历史（防篡改）。
- 由 `audit_log.record()` 写入，任务系统 / 版本系统 / cwrite 均调用。

## 3. 记录结构（见契约）

```json
{
  "op_id": "OP-000123",
  "ts": "2026-07-24T19:05:00",
  "agent": "writer-agent-01",
  "role": "writer",
  "model": "GPT-x",
  "action": "modify_chapter",
  "task_id": "TASK-CH132-WRITE",
  "files": ["chapters/drafts/CH132.md"],
  "result": "success",
  "detail": "生成正文 v2"
}
```

## 4. 必须记录的操作

| action | 触发方 |
|---|---|
| task_create / task_claim / task_start / task_submit / task_review / task_complete / task_fail | task_engine |
| ver_commit / ver_rollback | version_commit |
| cwrite（每次受控写） | controlled_write |
| status_update | status_update |
| gate_check（合规门） | compliance_gate |
| human_approve（人工 Gate） | 人工确认 |

## 5. 写入规则

- `audit_log.record()` 自动生成 `op_id`（递增）与 `ts`。
- `model` 来自 Agent 会话上下文（未知则 `"unknown"`）。
- 写入失败不得阻塞主流程，但须告警（审计丢失是严重事件）。
- `audit/` 不进 NKB 门禁，但受 `permissions.policy.yaml` 的 `audit-writer` 角色保护（仅工具可写）。

## 6. 与权限系统的关系

`permissions.policy.yaml` 决定「能不能写」；审计决定「写了有没有记录」。两者正交：权限拦截非法写，审计记录所有（含被拦截的尝试——拦截也记一条 `result=denied`）。

## 7. 查询（前瞻）

Phase 3 可提供 `audit query --agent X --action Y --since Z` 过滤。本规范仅保证记录完整。
