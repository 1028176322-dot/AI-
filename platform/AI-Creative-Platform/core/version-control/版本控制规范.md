# 版本控制规范（Version Control）

> 层级：Platform Layer — 版本控制系统
> 对应 Phase 1「必须」项：版本控制
> 配套契约：`core/contracts/revision.schema.yaml`
> 工具：`tools/version_commit.py`（CLI：`platform ver`）

## 1. 为什么需要内容版本控制

平台已有：NKB 版本、插件版本、构建版本。但**小说内容本身没有版本**。

没有内容版本会导致：
- 第 132 章改了 3 版，不知道哪版改了什么；
- 改崩了无法回滚；
- 找不到「问题引入于哪一版」。

本规范为**内容产物**建立版本链：每次修改产生一条 `revision`。

## 2. 版本范围

```
<project>/
└── versions/
    ├── chapters/    # 章节草稿版本
    ├── nkb/         # NKB 快照版本
    ├── outline/     # 大纲版本
    └── world/       # 世界观设定版本
```

每类产物一个文件：`<artifact_id>.yaml`，内部 `revisions:` 列表按时间递增。

## 3. Revision 结构（见契约）

```yaml
schema_version: 1.0.0
artifact_type: chapter
artifact_id: CH132
revisions:
  - id: REV-CH132-01
    before: null
    after: BUILD-132-01
    reason: 第一次生成
    approved: true
    author: writer-agent-01
    created: 2026-07-24T10:00:00
  - id: REV-CH132-02
    before: BUILD-132-01
    after: BUILD-132-02
    reason: 修复人物行为
    approved: true
    author: fixer-agent-02
    created: 2026-07-24T14:00:00
```

## 4. 操作

- `commit`：追加一条 revision（`before`=上一 after，`after`=新 BUILD）。
- `log`：列出某产物的全部 revision（可追溯改了什么）。
- `rollback`：将 `current` 指回某 REV 的 `after`（不删历史，仅切换指针），并记一条 `reason=rollback` 的 revision。
- `diff`（Phase 3）：比较两 BUILD 文本差异。

## 5. 与任务系统的关系

任务 submit 时若产出新 BUILD，应自动 `ver commit`（由 task_engine 钩子调用），使**每个任务的产物都进版本链**。这样：
- 任务 `completed` ↔ 一条 `approved` revision
- 任务 `failed`/`archive` ↔ 对应 revision 可 rollback

## 6. 与审计的关系

每次 `commit/rollback` 同时写 `audit/`（谁、何时、改了哪版、为什么），与任务审计同源。

## 7. 工具用法

```bash
platform ver --project-root <root> commit \
  --type chapter --id CH132 --after BUILD-132-02 --reason "修复人物动机" --author writer-agent-01

platform ver --project-root <root> log --type chapter --id CH132

platform ver --project-root <root> rollback --type chapter --id CH132 --rev REV-CH132-02
```
