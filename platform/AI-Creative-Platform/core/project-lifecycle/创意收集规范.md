# 创意收集规范（P0 Idea）

schema_version: 1.0.0
stage: P0
owner_role: idea-analyst
parent: 项目生命周期总规范.md

---

## 1. 目标

把零散想法转成**可评估的创意候选**，而不是立即创建正式项目。
创意阶段内容**不得进入正式 NKB**，因为项目尚未立项。

## 2. 来源

- 用户突然想到的设定、一句话脑洞、人物形象、世界机制、冲突场景；
- 某类题材方向、市场需求、AI 头脑风暴结果、外部作品启发。

## 3. 目录

Workspace 级（跨项目）或项目 `lifecycle/idea/` 二选一；推荐在立项前用 Workspace 级，立项后迁移进项目。

```
workspace/ideas/                # 跨项目，可选
├── inbox/                      # 未处理
├── evaluating/                 # 评估中
├── approved/                   # 已批准进入立项
└── rejected/                   # 已否决

# 或（项目内）
<project>/lifecycle/idea/IDEA.yaml
```

## 4. 创意卡结构

契约见 `core/contracts/idea.schema.yaml`。必备字段：

```yaml
idea:
  id: IDEA-20260724-001
  title: 道士经营现代化商城
  status: inbox          # inbox | evaluating | approved | rejected
  created_at: 2026-07-24
  source: user           # user | ai | external
core_concept:
  premise: 一个小道士在架空王朝经营现代商业体系
  novelty:
    - 道术与商业结合
    - 古代社会中的现代运营逻辑
initial_elements:
  protagonist: 小道士
  setting: 架空王朝
  central_hook: 用现代商业手段改变修行世界
unknowns:
  - 核心反派是谁
  - 主线目标是什么
  - 力量体系怎样限制主角
```

## 5. 状态流转

```
inbox → evaluating → approved →（P1 立项）
                ↘ rejected
```

- `approved` 的创意方可进入 P1 立项，生成 `sources/initiation/PROJECT_CHARTER.yaml`。
- `rejected` 的创意保留归档，不得进入正式项目。

## 6. 门禁

创意阶段**不要求**完整设定，但卡必须至少包含：

- `idea.id`（唯一）
- `idea.title`
- `core_concept.premise`
- `initial_elements.protagonist` 与 `setting`

缺任一项视为草稿（inbox），不得标记 approved。

## 7. 与 NKB 的边界

`idea.*` 全部属于“推测 / 未确认”，**禁止**被 `validate_nkb_sources.py` 或 `build_nkb_genesis.py` 当作事实源。
只有 P1 立项书 + P3 设计源才是 NKB 的合法上游。
