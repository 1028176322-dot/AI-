# 项目定义规范（P2 Definition）

schema_version: 1.0.0
stage: P2
owner_role: project-producer / market-reader-analyst

---

## 1. 目标

立项通过后，先确定作品“产品定义”（定位、受众、目标、边界），再进入 P3 设计。
本阶段产物属于**创作策略**，不是 NKB 事实。

## 2. 目录

```
<project>/lifecycle/definition/
├── PROJECT_BRIEF.yaml
├── AUDIENCE.yaml
├── POSITIONING.yaml
├── CREATIVE_STRATEGY.yaml
└── CONTENT_BOUNDARIES.yaml
```

契约：PROJECT_BRIEF / CREATIVE_STRATEGY 见 `core/contracts/project-brief.schema.yaml`、`creative-strategy.schema.yaml`；AUDIENCE / POSITIONING / CONTENT_BOUNDARIES 由 `validate_charter.py` 按通用 document 头 + 业务必填校验。

## 3. PROJECT_BRIEF（作品是什么）

```yaml
project_brief:
  genre: 玄幻经营文
  narrative_mode: 第三人称限知
  target_length: 2000000
  chapter_length:
    target: 3000
    min: 2500
    max: 4000
  serialization_mode: long_serial
  ending_type: closed
```

## 4. AUDIENCE（写给谁）

```yaml
audience:
  primary:
    description: 喜欢玄幻、经营和轻松爽感的男性网文读者
    expectations:
      - 主角行动有效
      - 节奏稳定
      - 持续成长
      - 商业扩张带来即时反馈
  dislikes:
    - 长时间无目标
    - 纯设定说明
    - 主角长期被动
```

## 5. POSITIONING（差异点）

```yaml
positioning:
  category: 玄幻经营
  differentiation:
    - 商业体系不是辅助，而是主推进器
    - 道术与现代组织管理融合
    - 爽点来自秩序建设和规模扩张
  comparable_dimensions:
    - 经营成长
    - 势力扩张
    - 技术代差
```

## 6. CREATIVE_STRATEGY（执行策略）

```yaml
creative_strategy:
  pacing:
    early: fast
    middle: layered
    late: convergent
  reward_cycle:
    small_reward_chapters: 3
    medium_reward_chapters: 10
    major_reward_chapters: 30
  conflict_mix:
    commercial: 0.35
    political: 0.25
    combat: 0.20
    character: 0.20
```

## 7. CONTENT_BOUNDARIES（红线）

```yaml
content_boundaries:
  prohibited:
    - 主角无理由屠杀平民
    - 无成本无限制造现代武器
    - 关键人物反复复活
  sensitive:
    - 真实历史映射
    - 宗教表达
```

## 8. 门禁

- 五项文件齐全且通过 `validate_charter.py`；
- `genre` 与 P1 Charter 的 `genre` 一致；
- `conflict_mix` 各项之和 ≈ 1.0（容差 0.02）；
- 无 `prohibited` 项为空（至少声明“无”而非留空）。

通过后 `lifecycle_status` 转 `defining` → 进入 P3。

## 9. 题材模板联动

`templates/<genre>/lifecycle/project-brief.defaults.yaml` 提供默认值；项目 brief 未填项可继承模板默认，但 `genre` 必须与 `project.yaml` 的 `template.id` 一致。

## 10. 与 P3 的关系

P2 决定“产品形态”，P3 在其约束下填充“具体内容”。二者冲突时，P2 的边界（CONTENT_BOUNDARIES）优先，P3 不得突破。
