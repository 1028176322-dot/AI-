## 1. 目标

回答：**这个项目为什么要做、它是什么、它不是什么、准备做到什么程度？**

立项阶段必须生成 **Project Charter（项目立项书）** 与 **Initiation Gate（立项门禁结论）**。

## 2. 目录与位置

```
<project>/lifecycle/initiation/
├── PROJECT_CHARTER.yaml
└── INITIATION_GATE.yaml
```

## 3. Project Charter 必备内容

契约见 `core/contracts/project-charter.schema.yaml`。

### 3.1 基础身份
```yaml
project:
  id: novel-dsf
  working_title: 道士也玩火力覆盖
  project_type: novel
  status: proposed          # proposed | initiated | active
  genre: xuanhuan
  subgenres:
    - 架空历史
    - 经营
    - 轻喜剧
```

### 3.2 核心命题
```yaml
concept:
  one_sentence_premise: 一个小道士用现代商业与火力逻辑改变架空王朝
  central_question: 当现代效率逻辑进入传统权力社会，会产生什么后果
  core_hook:
    - 道士
    - 商城
    - 火力覆盖
```

### 3.3 创作目标
```yaml
goals:
  length_target: 2000000
  serialization: true
  commercial_target: 长篇网络小说
  update_frequency: 每日
  target_completion: null
```

### 3.4 项目边界
```yaml
scope:
  included:
    - 主角成长
    - 商业扩张
    - 王朝权力斗争
  excluded:
    - 纯粹修仙升级
    - 无限制科技碾压
    - 多世界穿越
```

### 3.5 成功标准
```yaml
success_criteria:
  creative:
    - 核心卖点在前三章可感知
    - 主角目标明确
  structural:
    - 主线可支持长篇扩展
  operational:
    - NKB 可事件驱动维护
    - 日更生产链能够运行
```

## 4. 立项门禁（Initiation Gate）

必须回答（任一项否，则停留 P0）：

- 核心卖点是否清楚？
- 主角和核心冲突是否存在？
- 题材定位是否明确？
- 是否能支持目标篇幅？
- 与已有项目是否高度重复？
- 项目边界是否明确？
- 是否值得继续投入准备成本？

```yaml
# INITIATION_GATE.yaml
initiation_gate:
  status: pass            # pass | blocked
  decision: approved      # approved | rejected
  approved_by: user
  checked_at: 2026-07-24
  blockers: []            # 未通过时列出
```

## 5. 状态转移

- `status: pass` + `decision: approved` → `lifecycle_status` 由 `evaluating` 转 `initiated`，进入 P2。
- 否则停留 P0/P1，创意退回 `ideas/rejected` 或重新评估。

## 6. 边界

立项书是**创作策略文件，不是 NKB 事实**。其中的题材、目标、边界进入 P2/P3 后，才转化为设计源与正式 NKB 事实。
立项书不得直接写入 `NKB/`。
