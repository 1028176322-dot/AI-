## 1. 目标

正式构建小说内容，分成七个设计域。产物落入 `sources/design/**`，经 `validate_sources.py` 门禁后，成为 P4 NKB Genesis 的设计事实源。

## 2. 目录（与 NKB 信息源规范 §2 一致）

```
<project>/sources/design/
├── story/          # 故事核心
├── world/          # 世界设计
├── characters/     # 人物
├── factions/       # 势力
├── locations/      # 地点
├── items/          # 物品
├── abilities/      # 能力/功法
├── conflicts/      # 冲突系统
├── arcs/           # 成长/故事弧
└── foreshadow/     # 信息与伏笔系统
```

（既有 `skills/creatures/organizations/relationships` 仍可用，建议统一映射到上方语义；新项目以本结构为准。）

## 3. 七个设计域

### 3.1 故事核心（sources/design/story/）
- PREMISE / THEME / CENTRAL_CONFLICT / STORY_PROMISE / ENDING_DESIGN
- **STORY_PROMISE** 特别重要：回答“读者持续阅读会反复得到什么体验”，并定义 delivery_frequency（minor/medium/major）。

### 3.2 世界设计（sources/design/world/ + sources/canon/）
必须覆盖：世界边界、历史、地理、社会、政治、经济、文化、力量体系、技术体系、交通通信、资源来源、法律、不可变规则。
开写前只要求 **minimum_viable**：第一卷会用到的信息、直接约束主角行动的规则、不提前定义就会矛盾的内容。
`canon/immutable-rules.yaml` 的 `severity: fatal` 规则（如“死人不能复活”）必须由 `build_nkb_genesis` 注入 NKB Canon 并受 L5 审查守护。

### 3.3 人物设计（sources/design/characters/）
开写前至少完成：主角、第一卷核心配角、第一阶段对手、关键关系人物、组织领导者。
每人至少具备：身份 / 欲望 / 目标 / 恐惧 / 价值观 / 能力 / 限制 / 秘密 / 人物弧 / OOC 禁区 / 关系 / 说话方式 / 信息状态。

### 3.4 故事架构（sources/outline/）
全书级 → 篇章级 → 卷级 → 阶段级 → 章节级。
正式开写前至少：全书方向、第一大篇结构、第一卷完整结构、前 10–30 章细纲、前三章详细规划。

### 3.5 冲突系统（sources/design/conflicts/）
明确五类来源：internal / interpersonal / organizational / systemic / existential。禁止“只发生一些事件”而无来源归类。

### 3.6 成长系统（sources/design/arcs/）
主角能力 / 财富 / 势力 / 关系 / 地位 / 认知 / 世界影响力七维成长，避免只维护力量等级。

### 3.7 信息与伏笔系统（sources/design/foreshadow/）
开写前建立：核心真相、读者初始认知、主角初始认知、阶段性谜题、预设伏笔、可揭露顺序、禁止提前泄露内容。这直接服务 ReaderState。

## 4. 契约与门禁

- 每个实体单独一个 YAML 文件，含 `document` 头（见 `NKB信息源与入库规范.md` §19.1）。
- 结构校验见 `core/contracts/design-source.schema.yaml`（按 `document.type` 区分必填业务字段）。
- 门禁：`validate_sources.py` 扫描 `sources/design/**` 与 `sources/canon/**`，缺必填 / 缺 ID / 使用推测词未标记 / 无 `document.status` 均 FAIL。

## 5. 设计级别标注

每个设计文件应声明：
```yaml
design_level:
  required_before_writing: true
  detail_level: minimum_viable
```
`required_before_writing: true` 的项若缺失，P5 Readiness Gate 判 FAIL。

## 6. 与 P4 的关系

P3 产物是 P4 的**输入**。NKB Genesis 只从 `status: approved` 或 `required_before_writing: true` 的设计文件提取初始事实，不从此阶段的草稿（`inbox`/未批准）提取。

## 7. 状态转移

P3 设计源经 `validate_sources.py` 全 PASS 后，`lifecycle_status` 转 `designing` → 进入 P4。
