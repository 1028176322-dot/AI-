# 项目生命周期总规范（Project Lifecycle）

schema_version: 1.0.0
scope: 平台级前置阶段（Pre-production Lifecycle）

## 0. 为什么需要这一层

现有平台默认一个前提：**项目已经立项，题材、定位、世界观、人物、大纲、基础 NKB 都已准备好**。
平台实际覆盖的是：

```
项目已准备好
    ↓
正式写作（L1–L6）
    ↓
持续创作与维护
```

缺失的是前期：

```
创意产生 → 项目立项 → 市场与受众定位 → 创作策略 → 资料准备
        → 世界/人物设计 → 故事架构 → NKB 初始化 → 开写验收
```

本规范补全上述“前期生命周期”，使平台覆盖：

> 从一个想法，到立项、设计、资料准备、正式创作、审查、反馈，再到完结归档的完整小说项目生命周期。

## 1. 总架构（六阶段 + 运行时）

```
创意输入
   ↓
P0  Idea            创意收集
   ↓
P1  Initiation      项目立项（Project Charter + Initiation Gate）
   ↓
P2  Definition      项目定义（Brief / Audience / Positioning / Strategy / Boundaries）
   ↓
P3  Design          创作设计（故事 / 世界 / 人物 / 结构 / 冲突 / 成长 / 伏笔）
   ↓
P4  Knowledge        资料与知识准备（sources → NKB Genesis）
   ↓
P5  Readiness Gate   开写验收（六维检查）
   ↓
═══════════════════════════════════════════
P6  AI Creative Runtime（既有的 L1–L6 运行流程）
   NKB → L1 宪法 → L2 规范 → L3 规划 → Context → L4 Workflow
        → L5 Review → L6 Feedback
```

- P0–P5 称为 **Project Lifecycle（项目生命周期）**，不进入写作主栈编号。
- P6 才是既有平台运行流程；P5 的 Readiness Gate 是其唯一合法入口。

## 2. 阶段职责表

| 阶段 | 名称 | 核心产出 | 负责人角色 |
|---|---|---|---|
| P0 | Idea | IDEA 卡（inbox/evaluating/approved/rejected） | idea-analyst |
| P1 | Initiation | PROJECT_CHARTER + INITIATION_GATE | project-producer |
| P2 | Definition | PROJECT_BRIEF / AUDIENCE / POSITIONING / CREATIVE_STRATEGY / CONTENT_BOUNDARIES | project-producer + market-reader-analyst |
| P3 | Design | sources/design/**（故事/世界/人物/结构/冲突/成长/伏笔） | story-architect / world-designer / character-designer |
| P4 | Knowledge | sources/** + NKB-GENESIS-001 | knowledge-engineer |
| P5 | Readiness | READINESS_REPORT + READINESS_APPROVAL | readiness-reviewer |
| P6 | Runtime | 正式章节生产 | planner / writer / reviewer / fixer / knowledge-manager |

## 3. 编排器 Pre-flight（强制）

任何进入 P6 的任务（chapter.plan / chapter.write / review / fix）执行前，编排器必须：

```
1. 读取 <project>/lifecycle/status.yaml
2. 检查 lifecycle_status == "ready_for_writing"
3. 若不等于 ready_for_writing：
       返回 BLOCKED_PROJECT_NOT_READY
       附带 missing: [<缺失项列表>]
       绝不调用 Writer / Planner
```

缺失项从 P0–P5 各阶段制品推导（见 §7 与 `开写准备度规范.md`）。

`readiness_gate.py --preflight` 即该检查的可执行实现；CLI：`platform ready --project-root X --preflight`。

## 4. 与既有 L1–L6 的关系

- **L1 宪法 / L2 规范 / L3 规划**：在 P2–P3 产生的事实（定位、边界、结构）进入后，作为运行时约束。
- **NKB（L0 事实源）**：由 P4 的 Genesis 初始化，P5 验收其完整性。
- **Context Engine**：仅从“已批准事实 + 规划卡 + 上一章衔接 + 伏笔状态 + 时间线 + 读者态”构建，不临时拼入 inbox/research。
- **L4 Workflow + Capability / L5 Review / L6 Feedback**：完全沿用既有，不受本层改动影响。

## 5. 目录归属

平台侧（本目录 + `core/contracts/` + `tools/` + `templates/<genre>/lifecycle/`）：定义规则、契约、工具、题材默认。
项目侧：`lifecycle/`（P0–P5 制品）+ `sources/`（设计事实源）+ `NKB/`（Genesis 后唯一事实源）。

详见 `项目立项规范.md` §十（完整目录）与 `NKB信息源与入库规范.md`。

## 6. 角色分工（前期 vs 生产）

前期（P0–P5）角色，见 `ROLE_REGISTRY.yaml`：
idea-analyst / project-producer / market-reader-analyst / story-architect / world-designer / character-designer / knowledge-engineer / readiness-reviewer。

生产（P6）角色：
planner / writer / reviewer / fixer / knowledge-manager / system-maintainer。

**关键边界**：同一 AI 不得在 P3 阶段从“补设定”滑向“写正文”。正文只能在 P5 通过后由 writer 角色产出。

## 7. 项目级状态机

完整状态枚举（机器可读副本见 `readiness-report.schema.yaml` 的 lifecycle_status 枚举）：

```
idea → evaluating → initiated → defining → designing
     → preparing_knowledge → readiness_review → ready_for_writing
     → writing → completed → archived
```

状态写入 `<project>/lifecycle/status.yaml` 的 `lifecycle_status` 字段。
状态转移由各阶段 Gate 的产物驱动（见各阶段规范与 `项目状态机.md`）。

## 8. Legacy 项目祖父化（重要）

在“项目生命周期”建立之前已处于 writing 的项目（如本仓库的 `道法百年`）：

- 不强制删除已有正文、不强制重跑 P0–P5。
- `lifecycle/status.yaml` 直接置为 `lifecycle_status: writing`，并标记 `legacy_backfill_required: true`。
- 须在下次大版本门槛前补回最小化 lifecycle 制品（charter / brief / readiness 至少三项），使 `readiness_gate.py` 对未来变更可审计。
- 补回流程：按 P1→P5 顺序，用已知事实回填 `lifecycle/` 与 `sources/`；回填完成后将 `legacy_backfill_required` 置 false。

## 9. 工具与 CLI 一览

| 工具 | CLI 子命令 | 作用 |
|---|---|---|
| project_init.py | `platform init` | 脚手架 lifecycle/ + status.yaml |
| validate_charter.py | `platform charter` | 校验 P1/P2 制品契约 |
| validate_sources.py | `platform psrc` | 校验 P3 设计源门禁 |
| build_nkb_genesis.py | `platform genesis` | 从 sources 构建 NKB-GENESIS-001 |
| readiness_gate.py | `platform ready` | 六维开写验收 + 编排器 pre-flight |

## 10. 验收

本层视为“平台完整”的判据：

- 新增项目必须经过 P0–P5，且 `ready_for_writing` 后方可写作；
- 任何 AI 无法绕过 Readiness Gate 直接写正文（由 `readiness_gate.py --preflight` + 角色权限双重阻断）；
- Legacy 项目有明确祖父化标记与回填路径。

未达到时，平台不可用作文学生成入口。
