## 1. 目标

这是**目前最缺失**的一环。不能因为 `project.yaml` 存在、`NKB/` 目录存在，就允许 AI 写第一章。
必须增加 **Project Readiness Gate（项目开写门禁）**，六维全 PASS 且用户批准后才放行 P6。

## 2. 六维检查

### A. 项目完整性
```yaml
project:
  charter_approved: true
  brief_complete: true
  genre_selected: true
  audience_defined: true
  scope_defined: true
```

### B. 故事完整性
```yaml
story:
  premise_defined: true
  central_conflict_defined: true
  protagonist_goal_defined: true
  story_promise_defined: true
  ending_direction_defined: true
```

### C. 世界完整性
```yaml
world:
  core_rules_defined: true
  power_limits_defined: true
  initial_locations_defined: true
  first_arc_required_world_info_complete: true
```

### D. 人物完整性
```yaml
characters:
  protagonist_complete: true
  first_arc_core_cast_complete: true
  ooc_boundaries_complete: true
  initial_relationships_complete: true
```

### E. 结构完整性
```yaml
planning:
  series_direction_complete: true
  first_volume_outline_complete: true
  first_ten_chapters_planned: true
  first_three_chapters_detailed: true
```

### F. NKB 完整性
```yaml
nkb:
  genesis_completed: true
  schema_valid: true
  unresolved_conflicts: 0
  broken_references: 0
  terminology_valid: true
  reader_state_initialized: true
```

```yaml
  dimensions: {A: pass, B: pass, C: pass, D: pass, E: pass, F: pass}

# lifecycle/readiness/READINESS_APPROVAL.yaml
readiness_gate:
  status: pass
  approved_by: user
  approved_at: 2026-07-24
  entry_point: CH-001
  nkb_snapshot: NKB-GENESIS-001
```

## 4. 编排器 Pre-flight（强制）

P6 任何写任务前，编排器调用：

```
platform ready --project-root X --preflight
```

- 返回 `status: pass` 且 `lifecycle_status` 将置 `ready_for_writing` → 放行。
- 返回 `status: fail` → 输出 `BLOCKED_PROJECT_NOT_READY` + `missing: [...]`，**绝不**调用 Writer / Planner。

```json
{
  "result": "BLOCKED_PROJECT_NOT_READY",
  "current_status": "designing",
  "missing": [
    "protagonist.ooc_boundaries",
    "first_volume.ending_state",
    "power_system.cost_rules",
    "reader_state.initial"
  ]
}
```

## 5. 契约

见 `core/contracts/readiness-report.schema.yaml`：定义六维字段、枚举（pass/fail/warn）、`lifecycle_status` 合法枚举、缺失项结构。

## 6. 状态转移

`status: pass` + 用户批准 → `lifecycle_status` 转 `ready_for_writing` → 进入 P6 正式生产。
否则停留 `readiness_review`，列出 missing 回到对应阶段补足。

## 7. Legacy 例外

见 `项目生命周期总规范.md` §8：已处于 writing 的项目 `lifecycle_status: writing` + `legacy_backfill_required: true`，`--preflight` 对 legacy 项目直接放行（不阻塞既有生产），但要求补回 charter/brief/readiness 三项制品。
