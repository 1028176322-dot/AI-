## 2. 受控写隔离方案选型

### 2.1 威胁模型（为什么"扫描测试"不够）

纲要 §2.4 已识别：扫描测试只能发现 `open("w")` / `Path.write_text` 等**常见**违规，无法保证不可绕过。完整绕过面：

- 直接文件 API：`os.open` + `os.write`、`os.rename`、`shutil.copyfile`、`shutil.move`；
- 进程外手段：shell 重定向（`>`）、Git 直接写对象、`os.popen` 调用外部工具；
- 路径诡计：符号链接、相对/绝对路径穿越（`../`）、UNC/8.3 短名；
- 权限同源：若任务进程与 writer 共用同一系统账户和文件权限，"禁止绕过"只是应用层约定，可被任意代码无视。

因此必须在 **OS / 进程层**建立真实隔离，使普通任务进程在文件系统层面**根本无能力**写入 `chapters/`。

### 2.2 决策：独立受控写 Broker（否决子进程沙箱、否决纯 OS ACL）

选定方案（与纲要 §2.4 / §2.8 一致，采纳审查五的 Windows 工作区建议）：

```
[普通任务进程]  ── 低权限系统身份 TaskRunner，对 chapters/ 仅读
       │  请求写：operation + capability（多资源哈希 + nonces + 签名）
       │  本地受限 IPC（命名管道 / localhost AF_UNIX socket，仅本机、仅 Broker 接受）
       ▼
[受控写 Broker]  ── 独立系统身份 ChapterWriter，对 chapters/ 有写权
                   （Windows ACL 拒绝 TaskRunner 直写 chapters/）
       ① 校验 capability：签名(HMAC-SHA256) + nonce + single_use(消费即失效)
       ② 路径规范化：realpath + 拒符号链接 + 拒路径穿越 + 白名单目录
       ③ 多资源哈希：source / target / candidate_or_backup 三资源 expected_sha256 齐验
       ④ 状态/权限：经 authorize()(§2.8 分操作策略) + transition_state()(§2.9 CAS)
       ⑤ 执行：CAS 写（current_sha == expected）→ 临时文件 → 原子 rename 提交
       ⑥ 记录：不可变 task-event 日志(§2.10 哈希链 + 签名)
```

### 2.3 被否决的替代方案

| 方案 | 否决理由 |
|---|---|
| 子进程沙箱 | Windows 无原生轻量进程沙箱（对比 Linux seccomp/namespace）；Windows Sandbox 是整 VM，过重；文件系统权限隔离仍要回到 ACL，沙箱本身不提供 CAS/状态/事件中心化控制 |
| 纯 OS ACL（无 Broker） | 只能管"能不能写"，不能管"该不该写"；无法做 capability 消费、CAS 比较、状态机推进、事件日志等中心化强制；且 ACL 规则本身需可信进程维护 |

Broker 方案在 OS 层（ACL 剥夺直写权）+ 应用层（capability/CAS/状态/日志）形成**双重不可绕过**。

### 2.4 Windows 具体落地

- **每个“设备 × 项目”派生两个本地身份**：
  - `ACP_TR_<deployment_id>`：低权限，对 `chapters/` 仅 `读`；运行该项目受控任务进程。
  - `ACP_CW_<deployment_id>`：仅该项目 Broker 使用，对 `chapters/drafts`、`chapters/approved` 有 `写`。
- **NTFS ACL**：`chapters/drafts`、`chapters/approved` → 本项目 ChapterWriter 身份可写、本项目 TaskRunner 身份只读、其余非授权身份无写权限。
- **Broker 进程**：以本项目 `ACP_CW_<deployment_id>` 身份运行 Windows 服务，监听 localhost 受限端点；连接仅接受持有本机受保护 IPC token、并通过 Task/Session/Lease 复验的请求。禁止用独立临时进程替代正式服务。
- **capability 安全**：HMAC-SHA256 签名（密钥仅 Broker 持有，见纲要 §2.10 密钥托管：密钥不向 TaskRunner 开放，key_id 入 contract）；`nonce` 防重放；`single_use` 消费即失效；`signature` 防篡改。
- **路径防护**：所有写入路径经 `realpath` 规范化并校验白名单前缀；拒绝符号链接与 `..` 穿越、UNC/8.3 变体。

### 2.5 与纲要其余模块的集成边界

- `authorize(operation, task, actor, session, resources)`（§2.8）：在 **Broker 侧**统一校验，分操作策略。
- `transition_state(expected, next)`（§2.9）：每次写前后推进状态，CAS + 追加事件日志防并发覆盖。
- `task-event.schema.yaml`（§2.10）：每次写生成不可变事件（单调序号 + `previous_event_hash` + 认证 actor_id + HMAC/签名；链头定期签名锚定项目外）。
- 执行层禁子 Agent（§2.8）：harness 不向模型暴露 spawn/fork/delegate，工具网关再拒，违规记事件 `BLOCKED`。
