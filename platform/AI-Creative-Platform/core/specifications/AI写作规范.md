# AI 写作规范（Layer 2 · 行为规范）

> **定位**：五层架构的 **Layer 2 —— 行为规范（Specification）**。
> 规定 AI **怎样思考、怎样生成、怎样自检**。是 **Process Driven（过程导向）** 的核心：把大量问题在写作阶段消灭，而非等审查阶段再修。
> 本文件与 `审查体系.md`（Result Driven 检测）**互补**——规范管「写时不产生」，审查管「写后兜底」。

**设计原则（守元规则）**：本规范只规定「行为」，不重定义「检测项」。每层标注「对应审查检测项」并交叉引用 `checks/`，新增只改对应 `checks/` 文件。

---

## 层 1 · 思维规范（Thinking）

**禁止「打开就写」。** 生成前必须读取并确认以下上下文，无冲突才动笔：

- 人物档案（动机 / 语气 / 能力边界）
- 世界观与设定（已启用 / 已废弃）
- 时间线（年份 / 章节锚点）
- 伏笔登记（已埋 / 已收 / 进行中）
- 本章目标（要达成什么）
- 上一章结尾（衔接点）
- 本章已批准详细章纲（场景链、因果链、状态变化）
- 本章写作手法编排（每场景主/辅手法、环境功能、节奏与信息释放）
- 开头设计与结尾设计（承接点、进入方式、收束方式、下章桥梁）

**预写清单（Pre-Write Checklist）**：① 本章目标明确？② 与人物 / 世界观 / 时间线无冲突？③ 伏笔状态一致？④ 开头承接上章且匹配首场景？⑤ 场景手法与情节、环境适配？⑥ 结尾完成本章变化并为下章建立真实桥梁？
任一「否」→ 先解决再写，**不得带疑点动笔**。

---

## 层 2 · 生成规范（Generation Order）

**先规划、后生成；场景顺序依章纲，不套固定五段式：**

1. 核对本章目标、因果链和必须发生 / 禁止发生事项；
2. 核对每个场景的任务、进入状态、退出状态和环境功能；
3. 为每个场景选择适配的主手法、辅助手法、节奏与信息释放方式；
4. 设计开头如何承接上章并进入首场景；
5. 设计结尾如何兑现本章变化并桥接下章；
6. 按批准后的场景链生成正文，发现章纲不可执行时退回规划，不在正文中临时改设。

> 高潮并非每章必有动作峰值；过渡章、调查章、情感章可用发现、决定、关系变化或认知翻转形成该章峰值。正文不是机械填充，而是受章纲和手法编排约束的场景化实现。对应：`writing-strategy.schema.yaml`、`checks/story.md`、`checks/craft-adaptation.md`。

---

## 层 3 · 实时约束（Real-time Constraints）★最重要

**不是写完再查，而是写一句、查一句。** 逐句闸门，全过才继续：

```
写一句 → 现代词? → 人设? → 时间线? → 逻辑? → 重复? → 全 OK 才继续
```

- 对应检测：`checks/writing.md`（WR-F 流畅 / AI 腔）、`checks/business.md`（红线）、`checks/consistency.md`（一致性）、`checks/conflict.md`（冲突）。
- 这是把 Fatal / 硬伤**消灭在源头**的根本手段，也是「修一个坏两个」Regression 的釜底抽薪。

---

## 层 4 · 写作策略（Strategy）

写作手法必须由**情节任务 × 场景类型 × 环境作用 × 人物状态 × 读者预期**共同决定：

- **动作 / 战斗**：强调空间关系、选择—动作—即时后果和节奏变化；不得强制套同一拍数。
- **对白 / 谈判**：强调人物声口、潜台词、权力变化和言外信息（对应 `checks/dialogue.md`）。
- **调查 / 探索**：控制线索公平性、观察顺序、误导与发现，不用设定说明替代探索过程。
- **情感 / 关系**：通过行为、停顿、物件和环境反应呈现，不以旁白总结代替变化。
- **经营 / 修炼 / 日常**：必须有决策、代价、反馈或状态推进，避免流程流水账。
- **揭示 / 转折**：先提供可回溯线索，再完成认知变化，禁止无铺垫硬反转。
- **环境**：不是装饰；每个场景必须说明环境如何制造限制、机会、情绪压力、信息遮挡或象征呼应。

同一章可组合多种手法，但必须有一项主导手法；相邻章节不得因题材相似而自动复用同一种开头、节奏骨架和结尾句式。

---

## 层 5 · 写作预算（Budget）

每章定字数预算，并按本章场景任务动态分配。下表只是冲突升级章的**示例**，不是通用模板：

| 功能 | 预算 | 说明 |
|------|------|------|
| 开头 | 300 | 抓人，禁铺垫过长 |
| 铺垫 | 600 | 建冲突前因 |
| 冲突 | 700 | 对抗展开 |
| 高潮 | 900 | 最重笔墨 |
| 结尾 | 500 | 钩子 + 余韵 |

**禁止机械均分或照抄示例**：字数应跟随信息密度、情绪停留和动作速度。高潮不是所有章节的最大预算块；偏差超章纲预算 ±20% 时须说明原因并重新校准。
对应检测：`checks/chapter.md`（字数）、`checks/metrics.md`（ID 信息密度）。

---

## 层 6 · 禁止行为（Prohibited）

明确黑名单（预防层列出，审查层检测是否违反）：

- 解释 / 总结 / 重复 / 空话 / 鸡汤 / AI 腔
- 连续修炼 / 连续聊天 / 连续介绍设定 / 连续心理活动

对应检测：`checks/ai.md`（AI 腔锁词）、`checks/writing.md`（WR-F10）、`审查体系.md` §3 **Fatal B**（质量致命禁发布）、红线。

---

## 层 7 · 节奏控制（Pacing）

每章必须至少产生一种不可忽略的推进：**事件推进、冲突升级、人物选择、关系变化、信息揭示、状态改变或承诺兑现**。不是每章都必须同时出现战斗、高潮和物质收获，但不得写完后世界与读者认知均无变化。
对应检测：`checks/conflict.md`（CF01 无真实冲突 → Fatal B）、`checks/reader/`（RR 系列读者体验）。

---

## 层 8 · 质量自评（Self-Assessment）

写完**不直接交审查**，先自答：

- 章纲目标完成？关键因果成立？场景手法与情节/环境适配？开头承接自然？结尾由本章变化导出？读者获得了应有的理解、情绪兑现或追读动力？与近 10 章的首尾和节奏骨架有足够差异？

**全 YES 才提交**；任一 NO → 回到对应层修正再评。
对应：写作技能「阶段三 自检 + 读者审查」、`审查体系.md` §7.8 章节闭环之阶段一自检。

---

## 决策树（Decision Tree · 句级过滤器）

每写一句，强制走六问；任一「否」→ **删除**：

```
是否符合宪法？   ──否（违反七条任一条）──▶ 删除
是否推动剧情？   ──否──────────────────▶ 删除
是否塑造人物？   ──否──────────────────▶ 删除
是否增加信息？   ──否──────────────────▶ 删除
是否提升体验？   ──否──────────────────▶ 删除
是否值得字数？   ──否（漂亮但无功能/凑字数）─▶ 删除
   │（六问全过）
   ▼
保留
```

> 后两问为用户新增：**符合宪法**（与 L1 宪法双重闸，写时即拦违宪内容）、**是否值得字数**（剔除「写得好看但零价值」的灌水句，呼应 L2 规范·层5 预算）。
> 核心原则：**不是因为「能写」才保留，而是因为「有功能」才保留。** 一句话若无上述任一功能，即噪音。

---

## 绑定与接线

- **写作任务**须把八层 + 决策树实现为阶段闸门（准备 / 手法编排 / 生成 / 实时约束 / 预算 / 自评），并提交 `EVIDENCE-CH-NNN.yaml`。
- 每章领取任务时先由 `writing_strategy.py build` 生成写作手法编排；提交前由 `evidence-prepare` 建立证据，语义检查全部 PASS 后才可提交。
- **上游**：`AI写作宪法.md`（七条原则不可违反）。
- **下游**：`流程体系_小说创作.md`（Layer 3 执行）、`审查体系.md`（Layer 4 检测）、`审查体系.md` §7（五阶段回归闭环）。
- **过程 + 结果双驱动**：规范在写时消灭问题，审查在写后兜底检测，反补让两者持续进化。
