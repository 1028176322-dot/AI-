# 量化指标（metrics · 工程化计算定义）

> 本文件定义可量化、可机检的聚合指标。计算落地在 `tools/`（L4）。

## ID 信息密度（Information Density）
- **统计**：每章新增【角色 / 事件 / 设定 / 冲突 / 推进 / 情绪变化 / 成长】七类计数。
- **判定**：新增项合计 < 3 且字数 ≥2500 → 灌水预警；命中联动 ST05（-8）与 Fatal B（ID 预警未处理）。
- **目的**：防止 AI 3000 字只讲一件事。

## WBU 世界观利用率（World Building Utilization）
- **统计**：设定项【宗门 / 阵法 / 职业 / 国家 / 历史 / 神器】引用次数 ÷ 定义总数 = 引用率 %。
- **判定**：引用率 < 30% → 死设定预警，联动 WO02（-6）。
- **目的**：防止大量设定写了不用。

## CI 一致性指数（Consistency Index）
- **组成**：七维一致率均值 → 单一 %。
  - 人物一致率 CS01 / 设定一致率 LG05+WO01 / 时间一致率 CS02 / 地点一致率 CS04 / 装备一致率 CS03 / 技能一致率 CS03 / 剧情一致率 LG01
- **公式**：`CI = mean(七维一致率) × 100`。
- **判定**：CI < 95% → 一致性缺陷，门禁不通过（§7）。
- **目的**：长期一眼看设定是否前后打架。

## NH 健康度（Novel Health）
- **v4.2 重拆为五分量**（不再偏工程），从「综合分+CI+RE+AI+Risk」改为 **Story / Reader / Engineering / Narrative / Commercial** 五个正交维度：
  - **Story（编辑综合分）**：ES，含全部 13 编辑模块（①–⑬）。
  - **Reader（读者指数）**：Reader Index（含 Immersion）；代表「好不好看」。
  - **Engineering（工程健康）**：CI 一致性指数（0–100），代表「有没有 AI 错」。
  - **Narrative（叙事分量）**：⑪ 叙事审查模块分（NA Score），独立凸显叙事 craft——这是 v4.2 前被忽略的最大缺口。
  - **Commercial（商业分量）**：0.5×⑩商业性模块分 ＋ 0.5×PI（付费意愿）。
- **权重**：`NH = 0.30×Story + 0.30×Reader + 0.15×Engineering + 0.15×Narrative + 0.10×Commercial`（合计 100%）。
- **去重说明**：Story=ES 已含 ⑪ 叙事模块；NH 的 Narrative 分量与 ES 同源，默认**保留以独立凸显叙事重要性**。若需严格去重，可将 Story 分量改为「ES 扣除 ⑪ 权重」——体系默认不扣，以突出用户要求的「Narrative 独立」。
- **目的**：整体一眼看小说是否在变好；趋势看板画 NH 五维堆叠/曲线。
- **版本管理**：每次审查记 `vN`，NH/各分量/各模块分跨版本对比（如 故事 75→82→90、叙事 60→78），验证修改真变好。
