# 项目状态管理规范（Project Status Management）

> 层级：Platform Layer — 项目管理平面（Project Management Layer）
> 对应 Phase 1「必须」项：项目状态管理
> 配套契约：`core/contracts/project-status.schema.yaml`
> 配套工具：`tools/status_update.py`（CLI：`platform status`）

## 1. 为什么要单独做状态管理

此前平台的状态分散在两处：

- `lifecycle/status.yaml` —— 只回答「项目到了哪个**生命周期阶段**」（idea→writing→…），是**门禁视角**。
- 各组件内部（NKB、chapters、tasks）各自记录进度，但**没有一个统一入口**告诉 AI「当前项目到底在干什么」。

结果：AI 每次都要靠猜 / 靠读一堆文件来推断「现在写到第几卷第几章、卡没卡住」。

本规范新增 **`project/status.yaml`**，作为项目的**单一事实源（single source of truth）** for「当前生产状态」。它和 `lifecycle/status.yaml` 正交：

| 文件 | 回答的问题 | 谁写 | 何时变 |
|---|---|---|---|
| `lifecycle/status.yaml` | 项目在哪个**生命周期阶段**？能否开写？ | project_init / readiness_gate | 阶段跃迁（罕见） |
| `project/status.yaml` | 现在**在写什么 / 卡在哪 / 第几卷第几章**？ | status_update / 任务系统 | 每次生产推进（频繁） |

## 2. 文件位置与结构

```
<project>/
└── project/
    └── status.yaml
```

结构（权威字段见契约）：

```yaml
project:
  id: dao-fa
lifecycle:
  stage: writing            # 镜像 lifecycle/status.yaml 的 lifecycle_status
phases:
  idea: completed
  initiation: completed
  design: completed
  nkb_genesis: completed
  readiness: completed
  writing: active
  publishing: pending
current:
  volume:
    id: VOL-03
    name: 道生
  chapter:
    current: CH-132
    title: 炉火照夜
    workflow_current_step: review
  blocked: false
  blocked_reason: null
updated: 2026-07-24T19:00:00
updated_by: task-system
```

## 3. 字段语义

- `lifecycle.stage`：与 `lifecycle/status.yaml` 的 `lifecycle_status` 保持一致（由 `status_update` 自动镜像，禁止手改两处）。
- `phases.<name>`：`completed | active | pending`。一个阶段 `active` 时其余应为 `completed` 或 `pending`。
- `current.volume` / `current.chapter`：当前生产焦点。**AI 不再猜**，直接读这里。
- `current.chapter.workflow_current_step`：当前章节处于哪一步（plan / write / review / fix / nkb_sync / done）。供编排器决定下一步动作。
- `current.blocked`：是否阻塞。`true` 时 `blocked_reason` 必填。任务系统失败时由 `fail` 钩子置 `true`。

## 4. 写入规则

- 只有 `status_update` 工具与任务系统的状态钩子允许写 `project/status.yaml`。
- 普通生产 Agent（writer/reviewer/fixer）**禁止**直接写本文件（见 `permissions.policy.yaml` 的 `status-updater` 角色）。
- 每次写入必须刷新 `updated` 与 `updated_by`，便于审计追溯。

## 5. 与任务系统的关系

任务系统在以下时机自动更新 `project/status.yaml`：

- 某章节写作任务 `claimed` → `current.chapter.workflow_current_step = write`
- 进入 `reviewing` → `= review`
- `failed` → `current.blocked = true` + `blocked_reason`
- `completed` → 推进 `current.chapter.current` 到下一章（由 planner 生成的 task 依赖决定）

这样「状态」始终由**任务流**驱动，而非人工维护，避免漂移。

## 6. 工具用法

```bash
# 初始化（从 lifecycle 镜像 stage）
platform status --project-root <root> init

# 查看当前状态（JSON）
platform status --project-root <root> show

# 设置当前章节焦点
platform status --project-root <root> set --chapter CH-132 --step review

# 标记阻塞
platform status --project-root <root> block --reason "NKB 冲突未决"
```
