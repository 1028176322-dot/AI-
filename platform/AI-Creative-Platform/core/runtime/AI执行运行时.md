# AI 执行运行时（Execution Runtime · 检查点/重试/回滚）

> **定位**：目前 「规划 → 工作流 → 审查」仍是一条**全有或全无**的直线——某引擎失败（如 Battle Engine 报错）就得重跑整个 Workflow。**Execution Runtime 提供运行时基座**：缓存 / 恢复 / 检查点 / 重试 / 回滚，让失败**局部化**。
>
> **不属于新 Layer**：它是**运行时基座（runtime substrate）**，位于编排器之下、各引擎之上，不进入 L1–L6 主栈。与 Observability / 统一契约 同为跨切面运行时增强。

---

## 1. 五能力

| 能力 | 说明 | 触发 |
|------|------|------|
| 检查点 Checkpoint | 每段 / 每引擎产出后存快照（含 Build 标识） | 每个可独立步骤完成后 |
| 缓存 Cache | 同章重复上下文 / 事实请求命中缓存，不重复计算 | 相同输入已存在快照 |
| 恢复 Resume | 中断后从最近检查点续跑，不重头来 | 进程崩溃 / 人工暂停后重启 |
| 重试 Retry | 单引擎失败自动重试 N 次（换 impl / 降级） | 引擎返回错误 / 超时 |
| 回滚 Rollback | 某步引入 Regression → 回滚到上一检查点 | 回归审查（§7.1④）发现新问题 |

---

## 2. 失败局部化示意

```
Battle Engine 失败
  → Runtime 恢复最近检查点（Narrative + Character 已产出）
  → 仅重跑 Battle（重试 / 换 cap.battle.impl）
  → 续跑 Emotion + Description → 汇正文
（不重跑整章 Workflow）
```

- **与能力编排器配合**：检查点粒度 = 编排器「能力编排计划」的片段单位（`AI能力层.md` §4），故失败可精确到「某片段某引擎」，而非整章。
- **与 Build 关联**：检查点快照即 Build 标识锁定的状态（`流程体系_小说创作.md` §3.1）；回滚 = 切到上一 Build，保证可复现。

---

## 3. 与架构关系

```
编排器 Loop
   │
   ▼ Execution Runtime（基座）
   ├─ 检查点/缓存：每段产出即存
   ├─ 重试：单引擎失败局部重试
   └─ 回滚：Regression 触发→回上一检查点
        │
        ▼（失败时）
   不重跑整章，仅重跑受影响片段
```

> Execution Runtime 让系统具备**容错与续跑**能力——这是成熟 AI Agent 系统普遍引入的运行时层，也是用户指明「完善运行时」的重点之一：即便单个能力失败，整章生命周期不从头崩。
