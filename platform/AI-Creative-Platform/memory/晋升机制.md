# 经验晋升机制（Experience Promotion）

> 经验复用是跨项目平台的核心能力之一，但**绝不能把某部小说的特例误当普遍规律**。
> 本机制让经验从「项目问题」逐级晋升为「全局规则」，且任何经验都可降级。

## 四级数据隔离（与系统分层一致）

```
Global（全局可复用：宪法/规范/流程/检查项/能力引擎/Context Engine/编排器/脚本/已验证跨项目经验）
   ↓
Genre（题材可复用：各类型 Profile/规划/审查阈值/能力路由/术语种子/NKB 扩展）
   ↓
Project（项目私有：人物/世界观/时间线/伏笔/专名/大纲/正文/读者态/项目经验）
   ↓
Chapter（章节私有：规划卡/Final Context/草稿/审查报告/修复日志/章节状态）
```

下层可覆盖上层，但**不能反向污染**（Project 不能改 Global；Chapter 不能改 Project）。

## 经验分级目录

```
memory/
├── global/   跨多项目验证的通用经验（最高级）
├── genre/    仅对某种类型有效（按题材分子目录）
├── project/  仅当前小说使用（每个项目私有，不进平台）
└── rejected/ 被否决 / 降级 / 误报率高的经验
```

## 每条经验的结构

```yaml
id: MEM-X-000
level: global | genre | project
problem: 现象
root_cause: 根因
action: [处置步骤]
validated_projects: N
confidence: 0.0~1.0
status: active | deprecated
# genre 级附加：genre: xuanhuan
# project 级附加：scope: current_project
```

## 晋升门槛（最低标准）

| 晋升 | 条件 |
|------|------|
| 问题 → 项目经验 | 根因明确，修复后回归通过 |
| 项目 → 类型经验 | 至少 **两个同类型** 项目验证 |
| 类型 → 全局经验 | 至少 **三个不同类型** 项目验证 |
| 任意经验降级 | 引发副作用 / 误报率高 / 新模型已解决 → 移入 `rejected/` |

## 原则

1. **不靠单次发现直接升级为全局规则**——防止把单部小说特例当普遍规律。
2. Global Memory 仅收录跨多项目验证者；新增须经晋升门槛，不得由单次问题直接写入。
3. 经验与事实分离：经验进 `memory/`，事实进项目 `NKB/`；二者互不污染。
4. 与反馈体系呼应：L6 反馈的 System Update 沉淀为经验（global/genre/project），Knowledge Update 沉淀为 NKB 事实。
