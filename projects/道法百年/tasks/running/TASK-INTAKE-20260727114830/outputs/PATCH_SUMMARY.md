# 对话任务治理与项目全链路脚本复用

## 结果

- 对话中的“写 N 章”“审查第 A 到 B 章”“审查最新 N 章”会先被确定性解析，再创建平台 Goal、章节任务和 Task Packet。
- “写第 N 章”保留原有单章受控入口，兼容旧调用；数量、范围、全稿请求进入批量分发器。
- 多章写作按“规划 → 写作 → 审查 → 发布 → 下一章”串行推进，前一章未发布时后一章保持 backlog。
- 自动派生的写作、审查、修复和发布任务都会自动生成或刷新 Task Packet。
- 严格新项目使用 `chapters/drafts/` 与 `chapters/approved/`；旧项目继续使用原卷目录，不迁移既有内容。
- 审查通过前必须具备完整读者面板；审查 finding 会写入项目写作指导与回归检查。
- 严格项目的 `CH-NNN` 文件名已纳入统一章节索引，后续“写 N 章”能从现有最大章号继续。

## 主要实现

- 新增对话请求分发器和请求契约。
- 扩展任务 CLI 的 `dispatch`、`intake`、`run` 路由。
- 修复规划任务与写作后继的依赖状态、章节引用传播和规划任务收口。
- 补齐新项目 canonical 发布授权与目录映射。
- 补齐严格项目 outline 目录输入解析和无 `project.yaml` 时的安全回退。
- 新增真实临时项目端到端测试与自然语言解析单元测试。
