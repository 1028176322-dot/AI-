# 小说知识库（NKB · Novel Knowledge Base）

> **定位**：AI 创作操作系统的**唯一事实源（Single Source of Truth）世界数据库**。
> 它是「地基」，不进入流程编号。宪法 / 规范 / 规划 / Workflow / Review / 反补 / 编排器 全部**围绕它工作**。
>
> **最核心的边界**：NKB **只存事实，不存规则**。
> - ✅ 存：世界是什么样的、谁是谁、何时何地发生了什么、谁拥有什么、名词叫什么。
> - ❌ 不存：写作技巧、Prompt、审查规则、工作流——这些分属 宪法 / 规范 / 审查体系 / 流程体系，绝不下放。

---

## 0. 为什么是「数据库」不是「知识层」

早期「知识层」只是把散落 md 抽象为统一结构。但真正的缺口是：**没有一个唯一可信的世界状态**。

- 写作 L4 从这里**读取事实**，不凭记忆生成。
- 审查 L5 用这里**验证一致性**，而不是比对多个文档。
- 修复 L5 改正文时**同步更新**知识库。
- 经验反补 L6 发现**结构缺失**时，扩展知识模型（加组件 / 加字段），而不是让事实散落别处。

```
                        NKB（唯一事实源）
        ┌───────────────┼───────────────┐
        │               │               │
   写作 L4          审查 L5          修复 L5
   (读事实)      (以 NKB 验证)    (改正文+同步 NKB)
        │               │               │
        └──────▶ 编排器调度 ◀────────────┘
                       │
                  经验反补 L6（结构缺口 → 扩展模型）
```

## 1. 十一大组件（Schema + 示例）

> 字段示例取自《道士也玩火力覆盖》现有 canon（大晟王朝·永熙年号·肖凡），仅作 schema 说明，**不承载完整事实内容**（事实填充见 §4 follow-up）。

### K1 正史（Canon · 世界真相）— *整库最重要*
世界的底层规则与恒定事实。AI 写任何东西都不得违背。

| 字段 | 说明 | 示例 |
|------|------|------|
| 世界名称 | 唯一世界标识 | 大晟（架空，仿明礼制） |
| 时代 | 年号 / 纪元 | 永熙（帝萧咤） |
| 修炼体系 | 力量框架 | 武者登记制 / 道修双修 |
| 根本规则 | 世界不可破的定律 | 死人不能复活 |
| 力量来源 | 能量本质 | 气 / 灵 |
| 死亡规则 | 死亡判定与不可逆性 | 魂灭即真死，不可还魂 |
| 时间流速 | 时间是否有异常 | 常态 1:1 |
| 世界边界 | 已知疆域 / 禁区 | 中土十八州 + 北狄 + 虞国 |
| 禁忌 | 绝对禁区 | 禁私通北狄 / 禁御前妄议 |

> 「死人不能复活」即 Fatal A（审查体系）的**事实来源**——NKB 定规则，Fatal Gate 检测违规。

### K2 人物（Characters）
每个人不是只有名字，而是完整档案。OOC 检测以本组件为基准。

| 字段 | 说明 | 示例（肖凡） |
|------|------|------|
| 人物ID | 唯一键 | CHR-001 |
| 姓名 | 标准称谓 | 肖凡 |
| 年龄 | 当前年龄 | 永熙十二年 9 岁（1379） |
| 身份 | 社会地位 | 清虚观道童 |
| 性格 | 稳定特质 | 谨慎、现代思维 |
| 价值观 | 底层取向 | 厌弃官府、重因果 |
| 能力 | 已掌握手段 | 现代知识 / 基础道术 |
| 成长阶段 | 进度标记 | 启蒙期 |
| 目标 | 当前追求 | 活下去、查清身世 |
| 秘密 | 未公开信息 | 穿越者身份 |
| 关系 | 指向他人 ID + 类型 | CHR-002 王虎（挚友） |
| 口头禅 | 标志语 | — |
| 不能做什么 | OOC 边界 | 不主动暴露底牌 / 不效忠官府 |

> 每个对象含 `Version` + `Updated`（见 §2.1）：如肖凡当前 `Version 5 / Updated Ch132`（王虎死后关系更新）。

### K3 时间线（Timeline）
按章锚定的事实序列，**任何时间点都可查**，不留模糊。

| 字段 | 说明 | 示例 |
|------|------|------|
| 章节 | 锚点章 | 第 001 章 |
| 事件 | 该章确立的事实 | 肖凡入清虚观 |
| 年份 | 永熙纪年 | 永熙元年（1370） |

> 示例链：001 入观 → 015 识王虎 → 082 立商城 → 155 入京。AI 写任意章都能反查「此时应处何阶段」。

### K4 世界状态（World State · 实时 · 事件派生）
这是多数小说缺失的**实时快照**——世界「现在」什么样，不是设定，是状态。**由 K5 事件派生（见 §2.2），禁止直接手改**。

| 字段 | 说明 | 示例（派生自事件） |
|------|------|------|
| 京城控制权 | 谁掌盛京 | 萧咤（帝） |
| 皇帝知主角否 | 信息态势 | 未知肖凡 |
| 宗门敌对否 | 势力关系 | 黑虎帮敌对 |
| 商城营业态 | 资产状态 | 已营业（由 EVT-082「商城开业」派生） |

> 每条世界态带 `Version` + `Updated`（见 §2.1）。写作前读 World State，避免「写已倒闭的商城还在营业」；任何变更先写 Event，再由事件投影到此表。

### K5 事件（Events · 真相日志 · 驱动 K4/K7）
所有已发生大事的权威记录，AI 不会忘。**它是世界态与资源的唯一变更入口（见 §2.2 事件驱动）**。

| 字段 | 说明 | 示例 |
|------|------|------|
| 事件ID | 唯一键 | EVT-001 |
| 名称 | 事件 | 王虎死亡 |
| 章节 | 发生章 | 第 130 章 |
| 因果 | 影响 | 肖凡独行线开启 |
| Version | 变更计数 | 1 |
| Updated | 最近变更章 | Ch130 |

> 修复 L5 改事实时**写 Event 而非改 State**：王虎死亡 → 新增 `EVT-130` → 派生 `K2 王虎.存活=否` + `K4 势力关系`。事件可重放（§2.2）。

### K6 伏笔（Foreshadow）
不是正文，是**数据库**。自动提醒回收。

| 字段 | 说明 | 示例 |
|------|------|------|
| 伏笔ID | 唯一键 | FB-001 |
| 埋设点 | 章节 | 第 015 章 |
| 状态 | 未埋/进行/已收 | 未回收 |
| 最迟回收章 | deadline | 第 080 章 |

> 每个对象含 `Version` + `Updated`（见 §2.1）。超过最迟回收章仍未收 → Review 风险预警（读者遗忘）。

### K7 资源（Assets）
人物拥有什么，防「凭空多 / 凭空少」。

| 字段 | 说明 | 示例 |
|------|------|------|
| 装备 | 持有物 | 青锋剑 |
| 法宝 | 特殊器物 | — |
| 金钱 | 资产 | 铜钱若干 |
| 技能 | 已学 | 基础道术 |
| 丹药 | 消耗 | — |
| 称号 | 名号 | — |
| 关系 | 人际资产 | 王虎（挚友） |
| 势力 | 隶属 | 清虚观 |

> 每条资源带来源事件 `Version` + `Updated`（见 §2.1）：资源由 K5 事件经世界态派生，不手填（§2.2）。如「金钱 +10000」来自 `EVT-082 商城开业`。

### K8 术语（Terminology）
**唯一名称表**。AI 永远引用这里，不擅自改名。

| 字段 | 标准词 | 禁用同义 |
|------|--------|---------|
| 商城 | 好物商城 | 商店 / 肖记 / 铺子 |
| 修炼境界 | 炼体 / 筑基 | （按设定统一） |
| 组织 | 清虚观 | 清虚门 |
| 地名 | 盛京 | 应天 / 京城（混用须统一） |

### D1 故事状态（Story State · 动态）
AI 知道「自己写到哪了」。

| 字段 | 说明 | 示例 |
|------|------|------|
| 当前卷 | 卷名 | 第一卷 道生 |
| 主线 | 当前主轴 | 调查身世真相 |
| 阶段 | 进度段 | 第二阶段 |
| 完成度 | 百分比 | 35% |

### D2 读者状态（Reader State · 动态）
防提前剧透——区分「谁知道什么」。

| 字段 | 已知方 | 未知方 | 示例 |
|------|--------|--------|------|
| 皇帝身份 | 读者知 | 主角不知 | 萧咤即帝 |
| 幕后黑手 | 作者知 | 读者/主角不知 | 三皇子萧沛 |
| 伏笔真相 | 作者知 | 读者/主角不知 | — |

> 写作前查 D2：若某信息「读者不知」，则本章不得泄露（否则破坏悬念）。

### Knowledge Graph（知识图谱）
关系 / 组织 / 地图 / 势力**以图而非文字**存储，检索极快。

```
肖凡 ──挚友── 王虎
  ├──敌人── 李云
  ├──未知── 皇帝(萧咤)
  └──隶属── 清虚观

清虚观 ──敌对── 黑虎帮
黑虎帮 ──勾结── 虞国听雨阁
```

> 图谱是 K2/K5/K7 的关系索引层；正文写作 / 审查一致性均以图快速定位冲突。

## 2. 三条元规则（NKB 不可违反）

**M1 · 只记录事实，不记录推理**
- ✅ `肖凡拥有青锋剑。`（事实）
- ❌ `肖凡应该会喜欢李雪。`（推理，属人物分析，不放 NKB）
- 任何「可能 / 应该 / 倾向于」均不得入库。

**M2 · 唯一事实源（Single Source of Truth）**
- 任何人物 / 时间 / 装备 / 地名 **只出现一次**，在 NKB 内。
- 所有 Prompt、所有 AI、所有审查 **全部引用 NKB**，不得复制事实到章节 md 或别处。
- 章节正文是「事实的呈现」，不是「事实的定义」。

**M3 · 状态实时更新**
- 知识不是静态：王虎 第 130 章死 → NKB 立即由「存活」改「已殁」。
- 不更新则下一章 AI 又把人写活（典型 Regression）。
- 每次修复落盘，须同步更新 NKB 对应组件（见 §3 集成）。

## 2.1 对象版本化（Versioning）

> **本轮新增**：NKB 仅有 CHANGELOG（库级变更史）不够——审查需要知道「**单个对象何时被改**」。故规定：**每个 NKB 实体对象都带两个元字段**。

| 元字段 | 说明 | 示例 |
|--------|------|------|
| `Version` | 该对象变更计数，每次修改 +1（初始 1） | Character 肖凡 `Version 5` |
| `Updated` | 最近一次变更发生的章号 | `Updated Ch132`（王虎死后肖凡关系更新） |

**约束**：
- 所有实体对象（K1 正史条目 / K2 人物 / K3 时间线锚点 / K4 世界态条目 / K5 事件 / K6 伏笔 / K7 资源条目 / K8 术语 / D1–D2 条目）均含 `Version` + `Updated`。
- 任何修改（写作 L4 落盘 / 修复 L5 落盘）**必须**将该对象的 `Version +1` 并写入变更章号。
- 审查 L5 可据此判断「此对象最近是否被改」「改动是否引入 Regression」（如 `Updated Ch132` 后某章仍引用旧关系 → 冲突）。
- `CHANGELOG.md` 保留库级摘要；`Version/Updated` 是对象级追溯，二者互补。

## 2.2 事件驱动态（Event Sourcing）

> **本轮新增**：世界态（K4）与资源（K7）**不得直接手改**——直接改 State 会丢失「为什么变」，且无法回放。改为 **事件驱动**：所有变更经由 `K5 事件` 派生。

**数据流（单向派生）**：
```
Event（K5：发生了什么）
   │  applies
   ▼
World State（K4：世界现在什么样）   ← 由事件派生，不直接写
   │  delta
   ▼
Assets（K7：人物拥有什么）          ← 由事件 + 世界态派生
```

**示例**：
```
EVT-082「好物商城开业」(Ch082)
   → WorldState.商城营业态 = 营业
   → Assets.肖凡.金钱 += 10000（首月营收入账）
```
- 世界态 / 资源 = 事件的**投影（projection）**，不是手填值。
- **可回放**：给定任意章号 N，重放 `Ch001…ChN` 全部 Event，即可精确重建该章的 World State / Assets——用于回溯「第 300 章时商城是否营业」「第 132 章前王虎是否在世」。
- 修复 L5 改事实时，**写 Event 而非改 State**：如王虎死亡 → 新增 `EVT-130「王虎身亡」` → 派生 `K2 王虎.存活=否` + `K4 势力关系` 变化。这正是 M3 实时更新的正确落点。

> 事件驱动态让 NKB 从「快照库」升级为「可重放的真相日志」，是 CI 一致性校验与回归审查的更强底座。

## 2.3 派生数据（Derived Data · 自动生成）

> **本轮新增**：关系图 / 影响图 / 幂图（势力图）**不人工维护**，由 K2 人物 / K5 事件 **自动派生**——这承接 §2.2 事件驱动态「投影」思想，把「图谱」也变成派生产物而非手填值。

| 派生图 | 来源 | 说明 |
|--------|------|------|
| 关系图（Relationship Graph） | K2 人物.关系 | 谁与谁什么关系（挚友/敌人/隶属…），即 §1 知识图谱的关系层 |
| 影响图（Influence Graph） | K5 事件.因果 | 某事件触发哪些连锁影响（王虎死 → 肖凡独行线开启） |
| 幂图（Power Graph · 势力图） | K2/K7 | 各方势力资源/战力对比（清虚观 vs 黑虎帮 vs 虞国听雨阁） |

- **派生规则**：K2 关系变更 / K5 新增事件 → 重算对应图；图是投影，不是手填值（与 §2.2 事件驱动态同构）。
- **用途**：AI 分析「谁能动谁」「哪方占优」秒级可得；审查 CI 可比对图与正文是否一致（如正文写两势力和好，但幂图仍敌对 → 冲突）。
- 落点：`Derived.md`（见 §4 布局），由脚本从 K2/K5 重算，**不手动编辑**。

## 3. 与五层 + 编排器的集成

| 环节 | 与 NKB 的关系 |
|------|--------------|
| Context Engine | 从 NKB 抽取本章所需事实 → 经过滤/优先级/压缩/冲突解决 → 运行时上下文（人物 / 世界态 / 伏笔 / 时间线 / 读者态） |
| L4 Workflow | 按背景块写，**禁止私设事实**；术语一律引 Terminology |
| L5 Review | 以 NKB 为权威基准核对一致性 → 即 `审查体系.md` 的 **CI 一致性指数**（人物/设定/时间/地点/装备/技能/剧情 七维） |
| L5 Fix | 改正文**同时同步 NKB**（M3 实时更新）；如改了「王虎生死」须改 K2/K5 |
| L6 反馈 | 若发现**结构缺口**（如缺 D2 读者态）→ 扩展 NKB 模型，不把事实散落别处 |
| Orchestrator | 每轮 Loop 重建背景块（反映最新 NKB）→ 调度写 / 查 / 修 / 回归 |

> **版本化 + 事件驱动已落地（§2.1 / §2.2）**：NKB 现对每个对象带 `Version/Updated`，且 K4 世界态 / K7 资源由 K5 事件派生、可重放；审查 L5 可据此追溯「对象何时改、改动是否引入回归」，Context Engine 可按章重放事件精确重建任意章的世界态。
>
> **Fatal A 事实来源映射**：NKB K1「死人不能复活」「时间流速」「世界边界」等 → 审查体系 Fatal A（死人复活 / 时间线错误 / 世界观冲突）直接由 NKB 派生。NKB 定真相，Fatal Gate 执法。

## 4. 目录布局（落地落点）

```
小说_道法百年/NKB/
├── Canon.md          # K1 正史
├── Characters.md     # K2 人物
├── Timeline.md       # K3 时间线
├── WorldState.md     # K4 世界状态
├── Events.md         # K5 事件
├── Foreshadow.md     # K6 伏笔
├── Assets.md         # K7 资源
├── Terminology.md    # K8 术语
├── StoryState.md     # D1 故事状态
├── ReaderState.md    # D2 读者状态
├── Graph.md          # 知识图谱（关系/组织/地图/势力）
├── Derived.md        # 派生数据（关系图/影响图/幂图，由 K2/K5 自动派生，不手填）
└── CHANGELOG.md      # 变更 vN（M3 可追溯）
```
> **版本化约定（§2.1）**：上述每个实体文件内的对象均带 `Version` + `Updated` 两字段；**事件驱动约定（§2.2）**：`WorldState.md` / `Assets.md` 的内容由 `Events.md` 按章重放派生，不直接编辑。整合散落事实时（§4 Follow-up）须一并写入 Version/Updated 与对应 Event。

> **当前状态**：本文件只定义 **结构 + 三准则 + 集成关系**，不承载小说事实。
> 散落事实现位于 `时间线与人物关系图.md` / `小说简介.md` / `大纲_1000章总体规划.md` / `参考资料/反派设定.md` / 各卷章节 md。
> **Follow-up（待你确认启动）**：把上述散落事实**收敛整合**进 `NKB/` 十一文件，使 NKB 成为真正可机读的唯一事实源。整合前，NKB 仍为「结构规范」；整合后，写作/审查方可全量机读校验。

## 5. 与「知识层」旧版的区别

| 维度 | 旧 知识层（7 域） | 新 NKB（11 组件） |
|------|------------------|------------------|
| 定位 | 统一事实源（结构） | 唯一事实源世界数据库（SSOT） |
| 范围 | 正史/性格/世界/时间线/活动/伏笔/术语 | K1–K8 ＋ D1 故事态 ＋ D2 读者态 ＋ 图谱 |
| 动态态 | 无 | 新增 World State / Story State / Reader State 实时态 |
| 元规则 | 单一事实源 | 事实非推理 ＋ SSOT ＋ 实时更新（三条） |
| 图谱 | 无 | Knowledge Graph（关系/组织/地图/势力） |
| 边界 | 未强调 | 明令**不存规则/技巧/Prompt/工作流** |
